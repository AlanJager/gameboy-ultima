# 图块缓存和精灵行缓存

只少做两件重复的事：把图块字节拆成颜色索引，以及为一条扫描线扫 128 条 OAM。像素仍在光束的第一拍取样。缓存不保存最终颜色，也不改变旋转、翻转、扫描中写入的结果。

## 图块

| | |
| --- | --- |
| 键 | 显存偏移（已按镜像折回）+ 4bpp 或 8bpp。4bpp 以 32 字节对齐，8bpp 以 64 字节对齐 |
| 值 | 8×8 的颜色索引，`[u8; 64]`。0 表示透明，真正的 RGB 仍到调色板里查 |
| 大小 | 4bpp、8bpp 各 512 槽，直接映射。槽被别的图块占用就覆盖 |
| 依赖 | 只依赖这 32 或 64 个显存字节 |

取样时才做的事，**不**让这一槽失效：地图或精灵上的翻转、背景滚动、精灵坐标、旋转/缩放矩阵和参考点、马赛克、窗口、混合、`DISPCNT` 的映射方式（1D/2D）和页选择、调色板。

失效：

- 写到这组字节（8/16/32 位和 DMA 都进 `store_u8`），按折回后的偏移丢掉盖住它的 4bpp 槽和 8bpp 槽。同一地址两种位深各算各的，写一次两个都丢。
- `clear_vram` 丢掉全部槽。
- 换卡不改显存，槽还在。

背景和精灵如果读到同一段显存，用的是同一槽。写这一段，两边下次都会重新拆。

## 精灵行

| | |
| --- | --- |
| 键 | 扫描线号 0–159 |
| 值 | 这一行上的精灵序号列表（最多 128 个） |
| 大小 | 160 行 × 128 字节，大约 20KB |
| 依赖 | `DISPCNT` 第 12 位（精灵总开关）；每条精灵的 Y、仿射、隐藏、模式、形状、尺寸、双倍大小 |

`sprites_on_line` 只看这些位。所以下面的变化**不**清行表：X、翻转、图块号、优先级、调色板组、8bpp 位、马赛克位、旋转矩阵。矩阵仍然每次取样从 OAM 读，不缓存变换后的坐标。

失效：

- 写入前后，上面的覆盖字段变了，160 行全部作废。隐藏、改 Y、改大小都属于这里。旧行和新行都会在下次取样时重扫。
- 精灵总开关翻转时，行表全部作废。
- 只写矩阵参数（每条精灵 8 字节里的最后 2 字节）不改行表。

一次 `latch_span` 里同一行只问一次缓存。下一次调用若行表还在，直接拷序号，不再扫 OAM。

## 和脏行的关系

脏行决定要不要重新合成。图块和行表决定合成时少做多少解码。扫描中写入仍先标脏行：已经扫过的点保持旧颜色，后面的点用新数据。图块槽在写入时立刻丢掉，所以后面的点不会拿到旧索引。

模式 4/5 里，精灵图块从 `0x14000` 起。这里不再把这段地址按点阵页长取模，避免只弄脏第 0 行。
