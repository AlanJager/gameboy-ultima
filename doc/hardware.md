# ARM7TDMI 与一帧画面

这段程序模拟 **ARM7TDMI**。开机停在用户模式，`swi` 可以切到管理模式。画面是 GBA **模式 3** 的 240×160。

CPU 和画面不共用寄存器。CPU 用 `str` 把像素写进 `0x06000000`。PPU 按自己的行去读这块显存。写内存的那个周期就是通信，没有一条从 CPU 打到 PPU 的中断。

## 跑起来

```
cargo test
cargo run
cargo run --release
cargo run -- 卡带.gba
```

macOS 图形版可打包成独立应用，不需要通过 Terminal 启动：

```
./scripts/package-macos.sh
```

脚本会生成 `target/ULTIMA.app`。从 Finder 或 Spotlight 打开它即可；开发时使用 `cargo run` 仍会在当前终端中运行。启动时可从图库选择 ROM，也可在开发命令后附上 ROM 路径。

默认窗口由 GPUI 绘制。启动时可传 ROM 路径，也可在顶部操作栏载入 ROM。方向键是十字键，X 是 A，Z 是 B，A 是 L，S 是 R，Enter 是 Start，Backspace 是 Select，Space 暂停或继续。

顶部操作栏包含 ROM 加载、即时存档、即时读档和 BIOS HLE 快速路径开关。即时存档写在 ROM 旁的 `.state` 文件中，记录 CPU 和模拟硬件状态；读档只接受同一 ROM 的状态文件。`.sav` 仍用于游戏自己的 SRAM/Flash/EEPROM 存档，换卡或退出时写回。

启动后默认进入卡带图库。载入过的 ROM 会记录在应用数据目录的 `library.json` 中；macOS 路径为 `~/Library/Application Support/gameboy-ultima`。图库显示 ROM 头部的标题和游戏代码，双击卡带或在详情栏按“启动卡带”即可运行。没有自选封面时，运行约半秒后会保存一张游戏画面作为封面；详情栏的“选择封面图片”可导入 PNG 或 JPEG。原始 ROM 不会被复制，移动或删除 ROM 后可从图库重新载入。

未定义编码不再让整次运行停住。ARM 和 Thumb 都进入未定义模式：CPSR 存进这个模式的 SPSR，清掉 T、置上 I，下一条指令的地址放进 LR，PC 指到 `0x04`。没有完整的 BIOS 处理函数，`0x04` 放着一条 `movs pc, lr`，等于跳过这条指令再回到原来的模式。已经在未定义模式里又碰到未定义编码时，不再套一层异常，只把 PC 按指令宽度往前挪，避免死转在向量上。

IRQ 先到 `0x18`。BIOS 把 `r0`–`r3`、`r12` 和 LR 压进中断栈，再用 `ldr pc` 进入 `0x03FFFFFC` 里的处理函数。这个加载不看最低位，调用时是 ARM。处理函数用 `bx lr` 回到 `0x138`，`subs pc, lr, #4` 才把 SPSR 抄回 CPSR，被打断的 Thumb 会恢复 T。商业卡带仍不保证能玩完，整段 BIOS 和很多硬件都还没补全。

GPUI 使用独立模拟线程和原生文件选择器。BIOS HLE 快速路径默认开启：已实现的 SWI 由内置服务直接处理；关闭后，SWI 改走合成异常向量。GPUI 目前固定在 0.2.2；macOS 配置使用运行时 Metal shader 编译，构建需要 Xcode Command Line Tools。

## 寄存器

现在放五份。`r0`–`r15` 是用户和系统看到的那一份。管理模式、中断模式、未定义模式各有 SP、LR 和 SPSR。快速中断另有 `r8`–`r14` 和 SPSR。中止仍先共用用户这份。

当前模式写在 CPSR 的低 5 位。读寄存器时按这一位选份，换模式不用把旧值抄走。

开机是 ARM 状态、用户模式：`CPSR = 0x000000D0`，PC = `0x08000000`。读入卡带后切到系统模式（`0x000000DF`），寄存器仍是用户那一份，但 `msr` 可以改模式。用户栈在 `0x03007F00`，中断栈在 `0x03007FA0`，管理栈在 `0x03007FE0`。未定义模式有自己的 SP、LR 和 SPSR，开机时是 0，没有单独设栈。复位时这一份清掉。

认得出的 `swi` 直接做完，模式不变。认不出的才进异常：CPSR 存进管理模式的 SPSR，换到管理模式、清掉 T、置上 I，下一条指令的地址放进新的 LR，PC 指到 `0x08`。`movs pc, lr` 把 SPSR 抄回 CPSR，模式也就换回去。

`r15` 里存的是**下一条要执行的指令地址**。ARM 指令去读 `r15` 时，拿到的是这条指令的地址再加 8。`str` 把 PC 存出去时，存的是地址加 12。普通指令做完，PC 加 4。结果写进 PC 时，那个结果就是下一条地址，并且按 4 字节对齐。

Thumb 读 `r15` 拿到的是这条指令的地址加 4，做完 PC 加 2。`add rd, pc, #imm` 会先把这个值按 4 字节对齐。

## 指令

`disassemble` 把一个 32 位字译成文本。`step` 真正改寄存器，并返回这一步的周期数。下面这些数是每次访问都只要 1 拍时的长度：条件失败 1，数据处理 1，移位量在寄存器里再加 1，读内存 3，写内存 2，`ldm` 是寄存器个数加 2，`stm` 是寄存器个数加 1，跳转、`bx` 和 `swi` 是 3，`mul` / `mla` 是 2，长乘是 3，`swp` 是 4。空的块传输列表按 16 个寄存器算。地址落到更慢的区域时，多出来的拍加在这些数上。

ARM 状态的编码都有行为：

- 数据处理：`and` `eor` `sub` `rsb` `add` `adc` `sbc` `rsc` `tst` `teq` `cmp` `cmn` `orr` `mov` `bic` `mvn`。移位量可以是立即数，也可以在寄存器里。
- `ldr` / `str` / `ldrb` / `strb`，偏移是立即数或寄存器。加载和回写落到同一个寄存器时，留下读到的值。
- `ldrh` / `strh` / `ldrsb` / `ldrsh`，偏移是立即数或寄存器。加载和回写落到同一个寄存器时，留下读到的值。地址最低位是 1 时，`ldrh` 按没对齐的字读再转回来，`ldrsh` 改成读一个字节再做符号扩展。
- `ldm` / `stm` 的 `ia` `ib` `da` `db`。地址低两位忽略，读出的字不旋转。带 `^` 又不包含 PC 时用用户组。包含 PC 的 `ldm ^` 用当前组，然后把 SPSR 抄回 CPSR。用户和系统做这条会停住。基址在列表里又不是第一个时，存回写之后的值。`cmp` / `cmn` / `tst` / `teq` 把目标写成 PC 时，有 SPSR 就把 SPSR 抄回 CPSR，PC 不跳。
- `b` / `bl`。`bl` 把下一条指令的地址放进 LR。
- `bx`。目标最低位是 1 就置上 T，PC 按半字对齐。
- `mul` / `mla`，以及 `umull` / `smull` / `umlal` / `smlal`。
- `swp` / `swpb`。
- `mrs` 读 CPSR，特权模式也能读 SPSR。`msr` 在用户模式只改标志位；特权模式可以改控制位，包括模式本身。用户和系统写不了 SPSR。

条件不成立时只把 PC 加 4。`swi` 的编号取指令里的高 8 位。Thumb 的编号就是指令的低 8 位。条件不成立的协处理器和未定义编码只把 PC 加上去。条件成立时进入未定义向量 `0x04`，这一步返回成功。

T=1 时执行 Thumb。多数运算只能点名 `r0`–`r7`，并且总是改标志。`add`/`mov` 碰到高寄存器时不改标志。`bx` 按目标最低位在两套指令之间切换。`bl` 是连续两条：`blhi` 填写 LR，`bllo` 跳走，返回地址的最低位是 1。条件不成立的分支只把 PC 加 2。Thumb 的 `swi` 编号就是指令的低 8 位，返回地址是下一条 Thumb 指令。未定义编码同样进入 `0x04`，返回地址是下一条 Thumb 指令。空的 `ldmia` / `stmia` 按 16 个寄存器算：存出去的是这条指令的地址加 6，读则把那个字装进 PC。基址在列表里又不是第一个时，存回写之后的值。

每条操作的初态和终态放在 `data/arm` 和 `data/thumb`。一个文件一种操作，里面是机器码、执行前的寄存器和内存、执行后的结果。

```
cargo test --test arm
cargo test --test arm op_sub
cargo test --test thumb
cargo test --test thumb_gba
cargo test --test arm_gba
cargo test --test memory_gba
```

`roms/thumb.gba`、`roms/arm.gba` 和 `roms/memory.gba` 是 jsmolka/gba-tests 的套件，许可证是 MIT。它们从 `0x08000000` 跑完，再等垂直消隐，用模式 4 写结果。Thumb 全部通过时 `r7` 是 0，ARM 和内存全部通过时 `r12` 是 0，然后都停在原地跳转。

## 内存

小端。写 ROM 会被丢掉。

| 区域 | 地址 | 大小 |
| --- | --- | --- |
| EWRAM | `0x02000000` | 256 KiB |
| IWRAM | `0x03000000` | 32 KiB |
| I/O | `0x04000000` | `DISPCNT` 是普通半字。`VCOUNT`（`0x04000006`）和 `DISPSTAT`（`0x04000004`）的低 3 位按累计周期算 |
| 调色板 | `0x05000000` | 1 KiB |
| 显存 | `0x06000000` | 96 KiB。模式 3–5 的精灵图块从 `0x06014000` 起 |
| 精灵表 | `0x07000000` | 1 KiB，128 个精灵，每个 8 字节 |
| 卡带 | `0x08000000` | 32MB 窗口，`0x0A000000` 和 `0x0C000000` 是同一窗口 |
| 存档 | `0x0E000000` | SRAM 32 KiB，或 Flash 64/128 KiB。EEPROM 不在这里 |

工作内存、调色板、精灵表按上表的大小折回。显存先按 128 KiB 折回，再把 `0x06018000` 折到 `0x06010000`。8 位写入落到调色板，或显存低区时，这个字节填进对齐半字的两边。图块模式的低区到 `0x06010000`，位图模式到 `0x06014000`。再往上的显存字节写入丢掉，精灵表的字节写入也丢掉。半字和字写入仍按各自的字节落下。

`0x0E000000` 按字节访问。没有 `.sav` 时先当 32 KiB SRAM，空的是 `0xFF`，地址在 32 KiB 里折回。写完 `0x5555=AA`、`0x2AAA=55`、`0x5555=90` 就换成 128 KiB Macronix Flash，标识是 `C2` `09`，这次探测本身不算出改过。编程只能把 1 改成 0。整片擦除是 `AA 55 80 AA 55 10`，4 KiB 扇区以 `30` 结束。超过 64 KiB 时，`AA 55 B0` 后再写 0 或 1 换组。`F0` 退出标识模式。读入的 64 KiB 文件是 SST，标识 `BF` `D4`，不换组。

EEPROM 走 DMA3 的半字，只用每个半字的最低位。卡带不超过 16MB 时，`0x0D000000` 整段都是它；更大时只认 `0x0DFFFF00` 起的 256 字节。CPU 读 `0x0D` 仍是卡带。`11`、地址、一个 `0` 是读，随后读出 4 个 `0` 和 64 位数据。`10`、地址、64 位数据、一个 `0` 是写。9 或 73 位是 512 字节，17 或 81 位是 8 KiB。

退出时如果改过，写到卡带旁边的 `.sav`。512 或 8192 字节是 EEPROM，32768 是 SRAM，65536 是 64 KiB Flash，131072 是 128 KiB Flash。长度对不上就按 32 KiB SRAM 装进去，多的丢掉，少的补 `0xFF`。从文件读入之后，探测序列不再改芯片种类。

## 画面

模式 3 时，显存本身就是像素。一个像素 16 位：红在低 5 位，绿在中间 5 位，蓝在 10–14 位。`DISPCNT = 0x0403` 表示模式 3，并打开 BG2。

演示程序先写 `DISPCNT`，再读 `VCOUNT`。小于 160 就继续转，转到第 160 行才往显存填颜色。第 `y` 行是 `((y & 31) << 5) | 0x1F`，所以第 0 行是 `0x001F`，第 1 行是 `0x003F`，第 31 行和第 159 行是 `0x03FF`。

半透明、马赛克、旋转、窗口不放进这段光束程序。各自一段短程序，写完寄存器就停住。测试先看寄存器落在精灵表、`MOSAIC` 或窗口寄存器，再对两个像素：一个点看出效果，另一个点确认位图没有被改掉。

```
cargo test semi_transparent_sprite
cargo test mosaic_sprite
cargo test rotate_sprite
cargo test window_clips
```

光束和 CPU 共用累计周期。每 4 个周期锁一个像素，用的是这个周期结束时显存里的颜色。锁进去之后，显存再改也不会回头改这个点，要等下一帧光束再次经过。程序停住时下一帧才扫完 27 行，所以画面上半是新渐变，下半还是空转那一帧留下的黑。`render_frame` 仍是把当前显存整帧重读一遍，和光束锁住的画面不是同一块缓冲。

每个点先问各层要颜色。这一层没有颜色，就看后面的层。优先级是 0、1、2、3，数字小的在前。同一档里，精灵盖过背景；精灵之间序号小的在前；背景之间编号小的在前。都没有颜色时，用调色板 `0x05000000` 的背景色。模式 3 和模式 5 的背景 2 每个点都有颜色，`0x0000` 也算黑色，不是镂空。模式 4 的色号 0 显示这张表的第 0 色，同样不镂空。

模式 0 的四个背景、模式 1 的背景 0 和 1，扫描时读图块地图。`BGxCNT` 给出图块区、地图区、优先级，以及 16 色还是 256 色。`BGxHOFS`、`BGxVOFS` 加到屏幕坐标上，再按地图宽高绕回去。一格地图是 16 位：图块号、翻转、16 色时的调色板组。256 色时忽略调色板组，下标直接进 `0x05000000` 起的 256 色，图块每块 64 字节。0 号颜色镂空。地图宽或高超过 256 时，按 32×32 一块往后拼。每个背景先按模式选定公式，再交出一个颜色。模式 0 用文字地图。模式 3 的背景 2 是 240×160 的 16 位颜色。模式 4 仍是 240×160，每个点一个色号，查 `0x05000000` 的 256 色。模式 5 的颜色和模式 3 相同，大小是 160×128，放在左上角，外面这层没有颜色。模式 4 和模式 5 的 `DISPCNT` 第 4 位选择 `0x06000000` 或 `0x0600A000` 那一页。模式 3 不看这一位。模式 1 的背景 2、模式 2 的背景 2 和 3 用旋转缩放：`dx`、`dmx`、`dy`、`dmy` 和原点都是这一层自己的，8 位小数。地图项是一个字节的图块号，固定 256 色。坐标超出地图时，`BGxCNT` 第 13 位决定镂空还是绕回。

`DISPCNT` 的第 12 位打开精灵。扫描到一个点时读精灵表：矩形盖住这个点，并且图块颜色不是 0，就加一层。16 色用 `0x05000200` 起的那组调色板，0 号颜色镂空。全 0 的表项是一个放在左上角的 8×8 精灵，要藏起来就把属性第 9 位置上。横竖翻转、8×8 到 64×64 的尺寸、一维和二维排图块都认。属性 0 第 8 位打开时，翻转位改成矩阵编号，绕精灵中心做旋转缩放；第 9 位同时置上时，判定框放大一倍。矩阵放在精灵表里，每组 4 个 8 位小数的系数。

马赛克、窗口和混合都不改优先级。马赛克让这一层改去读格子左上角的颜色，背景和精灵各用 `MOSAIC` 里自己的宽高，还要 `BGxCNT` 或精灵属性单独打开。窗口先决定这个点允许哪些层、以及允不允许混合。`WIN0` 优先于 `WIN1`，再是精灵窗口，剩下的点用窗口外的设置。混合发生在排序之后：正常模式只对半透明精灵做透明混合；透明混合还认第一目标；增亮和变暗只处理第一目标，半透明精灵不再另算。第二目标必须是紧挨在下面的那一层，没有就看背景色。

## 时钟

CPU 和 PPU 共用一个累计周期，对应 16.777216 MHz 的晶振。`step` 成功时把这一步的 `cycles` 加进去。停住的指令不加。

指令还是一条一条解释执行，没有编译成宿主代码。同一地址、同一机器码第一次拆开位域后记在一张直接映射的表里，下次直接拿结果。写到 BIOS、片内 RAM、显存，或重新装入卡带，相关的行作废。总线用一张日程表往前跳，热路径只比较累计拍数和缓存的下一次截止拍，排程或弹出时才重算。表上有：定时器溢出（0 到 3，级联的那路跟着前一路）、一行的起点（第 160 行是垂直消隐，也看行匹配）、水平消隐（这时才开消隐 DMA）、声音采样。同一拍按这个顺序处理。截止拍还远时，窗口一次最多连跑 8 条，但每条仍按自己的拍数加上去，不会跨过定时器或采样。像素仍是 4 拍里的第一拍合成一次，一行的精灵先收成短表。160 行各用 1 位记下要不要重画，一共 20 字节。点阵模式的显存写入只标那一行；调色板、滚动、混合，以及图块模式的显存，整屏标脏。精灵按它的纵坐标和高度标行，写之前盖住的行也标上。一行扫完就清掉合成位；光束正停在这行上又写入时，这一位留到下一帧。窗口只贴重新合成过的行。没有改成消隐才把整行画完，也没有按一小段像素来标。图块解码和每行精灵名单另有缓存，键和失效写在 `doc/tile-sprite-cache.md`。调色板仍在取样时查。

一行 1232 个周期，前 960 个画 240 个像素，后 272 个是行消隐。一帧 228 行，共 280896 个周期。`VCOUNT = (累计周期 % 280896) / 1232`。写 `VCOUNT` 留不下值。

`DISPSTAT` 的低 3 位也按这个位置算，写不进去。第 0 位在第 160–226 行是 1，第 227 行是 0。第 1 位在每一行的后 272 个周期是 1，垂直消隐里也一样。第 2 位是当前行号等于高 8 位里写下的行号。第 3–5 位是这三件事的中断允许，会留下来。允许位开着时，对应状态从无到有的那一拍把 `IF`（`0x04000202`）的同一位置上。写 1 清掉这一位。消隐一直持续时不再重复置位。

访问分第一次和接着上一次。地址正好接在上一次后面，用接着的拍数，否则用第一次的。片内：BIOS、IWRAM、I/O 任何宽度都是 1 拍。EWRAM 是 16 位总线，8 位和 16 位 3 拍，32 位 6 拍。调色板和显存 16 位 1 拍、32 位 2 拍。精灵表 1 拍。画面正在画可见行时，再碰这三块，每个 16 位拍再加 1，精灵表加 1。强制白屏时不加。

卡带看 `WAITCNT`（`0x04000204`）。`0x08000000` 是第 0 档，`0x0A000000` 是第 1 档，`0x0C000000` 是第 2 档。`0x0E000000` 的 SRAM 按字节算。复位值是 0：SRAM 和三档第一次都是 4 拍，接着分别是 2、4、8 拍。32 位访问是一次第一次加一次接着。第 14 位打开后，不占卡带的拍会预先读入最多 8 个半字，取指命中时每个半字 1 拍。第 11、12 位是 PHI，不加进 CPU。

| 位 | 含义 | 0 | 1 | 2 | 3 |
| --- | --- | --- | --- | --- | --- |
| 0–1 | SRAM | 4 | 3 | 2 | 8 |
| 2–3 | 第 0 档第一次 | 4 | 3 | 2 | 8 |
| 4 | 第 0 档接着 | 2 | 1 | | |
| 5–6 | 第 1 档第一次 | 4 | 3 | 2 | 8 |
| 7 | 第 1 档接着 | 4 | 1 | | |
| 8–9 | 第 2 档第一次 | 4 | 3 | 2 | 8 |
| 10 | 第 2 档接着 | 8 | 1 | | |
| 14 | 预取 | 关 | 开 | | |

`0x04000130` 是按键。低 10 位松开是 1，按下是 0，写进去留不下。`0x04000132` 的低 10 位选出哪些键。第 14 位打开时，条件成立就把 `IF` 的第 12 位置上。第 15 位要求选中的键全都按下，否则有一个按下即可。窗口每帧把键盘写进这 10 位。没有窗口时读到的是全部松开。

`IE`（`0x04000200`）选出哪些来源可以报，`IME`（`0x04000208`）的第 0 位是总开关。`step` 取指令前，如果 IME 开着、IE 和 IF 有重合、并且 CPSR 的 I 是 0，就进入中断模式：置上 I、清掉 T，LR 是下一条指令的地址加 4，PC 指到 `0x18`。`b 0x128` 之后是 `stmfd sp!, {r0-r3, r12, lr}`、`mov r0, #0x4000000`、`add lr, pc, #0`、`ldr pc, [r0, #-4]`。最后这条从 `0x03FFFFFC`（也就是 `0x03007FFC`）取出处理函数，低两位丢掉，保持 ARM。处理函数用 `bx lr` 回到 `0x138` 的 `ldmfd` 和 `subs pc, lr, #4`。中断栈从 `0x03007FA0` 往下长。画面和声音在处理函数执行时继续走周期。

四路定时器从 `0x04000100` 起，每路一个计数半字和一个控制半字。分频是 1、64、256、1024 个 CPU 周期，按累计周期对齐，启动时不清相位。控制位第 2 位改成数前一路的溢出，0 号忽略这一位。停下时读到的是停住的计数。写入的重载值要到启动或溢出才抄进计数。溢出并且第 6 位开着时，把 `IF` 的第 3 到第 6 位置上。

## 声音

四路音源和画面共用累计周期。音源自己的时钟是 CPU 的四分之一。`0x04000084` 的第 7 位是主开关，关掉以后输出是 0，再写通道寄存器也不生效。

`0x04000080` 选择哪一路进左声道、右声道，以及两边的音量。`0x04000082` 的低两位是这四路合计后的比例：`00` 和 `11` 是 25%，`01` 是 50%，`10` 是 100%。

方波 1 在 `0x04000060`，带扫频。方波 2 在 `0x04000068`。波形在 `0x04000070`，32 个 4 位样本放在 `0x04000090`，每个字节先放低 4 位。噪声在 `0x04000078`。频率倒数到 0，占空比或样本就进一步。长度、扫频、音量包络按 512 Hz 的节拍走。`Bus::audio` 给出音源此刻的左右幅度。

`0x04000088` 的 `SOUNDBIAS` 隔固定的 CPU 周期读一次这个幅度，推进一个环形缓冲。高 2 位：`00` 是 512 周期（32768 Hz），`01` 是 256，`10` 是 128，`11` 是 64。读到的数加上低 10 位偏置，夹到 `0x000`–`0x3FF`，再右移 1 到 4 位。偏置不加进 `Bus::audio`。

样本是数据面，采样率、偏置和丢样计数是控制面，不写进样本里。模拟线程只往环里放。窗口的播放线程只从环里取，取不到就睡 1 毫秒，不让模拟等它。环能放 8192 帧；满了丢掉新样本，`audio_overruns` 加一。`audio_samples` 是还没被播放线程取走的那段，给测试和 `wav` 用。播放线程在跑时，不要再靠它读完整历史。

## DMA

DMA0 从 `0x040000B0` 起，DMA1 从 `0x040000BC`，DMA2 从 `0x040000C8`，DMA3 从 `0x040000D4`。每路 12 个字节：源地址、目标地址、次数、控制。前三项读出来是 0。控制位低 5 位留不下。

四路共用同一种搬法。单位是 16 位或 32 位。源和目标各自可以加、减，或者停在原地；目标还可以「加，搬完再回到起点」。源地址控制写 3 时按加处理。使能位从 0 变成 1 时，把这时的源、目标和次数抄进内部指针。立刻开工跑完这一块就清掉使能。垂直消隐、水平消隐、特殊开工可以打开重复：下一次触发重装次数，源地址接着走，目标只有选了重装才回到起点。搬完一块并且开了完成中断时，`IF` 的第 8、9、10、11 位分别对应 DMA0、DMA1、DMA2、DMA3。

次数：DMA0、DMA1 和 DMA2 看低 14 位，写入 0 表示 `0x4000`。DMA3 看 16 位，写入 0 表示 `0x10000`。每搬一个单位，源和目标各自按那块内存的等待来计拍，加进累计周期，定时器和画面一起走。地址每次正好加上宽度时，下一次用接着的拍数。这一路正在付这几拍时，自己不再重入。

开工时机在控制位第 12、13 位。0 是使能后立刻搬。1 是进入第 160 行。2 是每一行走到第 960 拍，垂直消隐里也算。3 对 DMA0 是禁止的，使能位留着也不搬。对 DMA1、DMA2 是声音队列：队列里不超过 16 字节就搬 4 个 32 位字，次数和宽度位不用。没有新的定时器溢出、队列也还高于 16 字节时，追上周期不会再进补数。正在付周期时的补数只搬字节，不算等待，也不把新拍数滚进同一笔账。对 DMA3 是可见行的水平消隐，垂直消隐里不搬。同一拍要开多路时，号码小的先搬。DMA0 的源地址到了 `0x08000000` 及以上时，读出来是 0。

## swi

没有放进那 16KB 的 BIOS。下面这些编号在调用处做完，模式不变。除数是 0 时，6 号和 7 号的商记 0，余数仍是被除数。认不出的编号仍进入 `0x08`。`0x0D` 把 `r0` 设成 `0xBAAE187F`。

`0x02` 停机，直到 `IE` 和 `IF` 有重合。`0x03` 只等串口、按键或卡带。`0x04` 等 `r1` 里的中断；`r0` 不是 0 时先丢掉旧标志。`0x05` 就是丢掉旧的垂直消隐再等下一次。标志记在 `0x03007FF8`：进 IRQ 时把这次的 `IE & IF` 或进去，等到的位在返回时清掉。`0x27` 把 `r2` 的低 8 位写进 `0x04000301`，最高位是 1 就按 `0x03` 停，否则按 `0x02` 停。

`0x00` 清掉 `0x03007E00` 起的 `0x200` 字节，三条栈放回开机的位置，然后跳走。`0x03007FFA` 是 0 时去 `0x08000000`，否则去 `0x02000000`。`0x01` 按 `r0` 的位清板载内存、片上内存（留下最后 `0x200` 字节）、调色板、显存、精灵表、串口、声音和其余 I/O，并且总是把画面切到强制白屏。`0x26` 清掉内存和 I/O，跳到 `0x08000000`。

`0x06` 是有符号除法，商在 `r0`，余数在 `r1`，商的绝对值在 `r3`。`0x07` 把被除数和除数对调。`0x08` 开方，向下取整。`0x09`、`0x0A` 是反正切，角度一圈是 `0x10000`，只取角度的高 8 位参加正弦。

`0x0B` 按 16 位或 32 位整块复制，也可以用一个值填满。`0x0C` 按 32 位，字数向上取整到 8 的倍数。源地址落到 BIOS 里就什么也不做。`0x10` 到 `0x18` 是位展开、LZ77、哈夫曼、游程和差分。显存那几路按 16 位写，哈夫曼按 32 位写。`0x0E`、`0x0F` 算背景和精灵的仿射参数。

`0x19` 把声音偏置慢慢收到 0 或 `0x200`，采样率那两位留着。`0x1F` 按波形数据 `+4` 处的频率、音高和微调算出定时器要用的频率，中央 C 是 60。`0x1A` 到 `0x1E`、`0x20` 到 `0x24`、`0x28`、`0x29` 只记下工作区和模式，调用本身返回，不播放序列。`0x2A` 往 `r0` 写下 36 个指针，都指向 `0x188` 的 `bx lr`。`0x25` 没有另一台机器，`r0` 返回 1。
